# Reprobuild case addressability through the canonical `ct test` surface

Companion prose for `ct-test-surface-addressability.json`. The JSON is the
machine-readable half, and it is what
`tests/integration/t_ct_test_surface_case_addressability.nim` holds the tree
to. Both files have one producer. After the inventory
(`benchmarks/reports/reprobuild-suite-m0-inventory-sources.json`) is current,
regenerate both from the dev shell, which puts `ct-test` on `PATH`:

```sh
CT_TEST=<path to a ct-test build> \
CT_TEST_PROVENANCE="<what that build is>" \
  python3 scripts/ct_test_surface_addressability.py
```

The script refuses to measure against a stale inventory. It writes the JSON
and rewrites the **Current figures** block below from it. That block is the
only place in this file that states a figure about the current tree, and
`python3 scripts/ct_test_surface_addressability.py --check` refuses the block
when it no longer matches the JSON. The same check refuses a ledger that never
measured a source the inventory tracks, or that was computed against another
inventory. It needs no build, and `scripts/check_suite_case_counts.sh` runs it
at every push. If only the prose around the block changed,
`--write-markdown` re-renders the block from the checked-in JSON without a
surface.

The figures under **History** describe one past measurement, at the revision
they name. Nothing maintains them, and they are not the current state.

## What is measured, and what it is not

CodeTracer publishes a test surface: `ct test discover` / `ct test run`,
driven by a provider registry. Reprobuild has always been able to enumerate
its own cases — a test binary built by the codetracer-nim fork answers
`--list-json` with a row per case — but that is Reprobuild reading a compiler
protocol, not Reprobuild reading CodeTracer's surface. This measurement is
about the surface.

It measures **addressability**: can every case this repository declares be
*named and selected* through `ct test`, under an identity that is stable, with
counts a machine can read? It says nothing about **execution**. The two are
separate and the second is not close: see "What the surface cannot do" below.

## How the measurement is taken

| | |
|---|---|
| Command | `ct-test test discover --workspace <repo> --json`, one invocation |
| Discovery scope | `auto` — the surface's default, which is the workspace's own VCS inventory. Vendored `references/` trees and ignored paths are excluded |
| Surface | located as `libs/ct_test_surface` locates it: `$CT_TEST`, then `ct-test` on `PATH`, then `ct`. The JSON records the binary's content hash and whatever `$CT_TEST_PROVENANCE` declared, never a host-local path |
| Ground truth | `benchmarks/reports/reprobuild-suite-m0-inventory-sources.json` (`staticCaseCount`), produced by a different scanner in a different language in a different repository |
| Order | the inventory first, then this ledger. Case-count disagreements are computed against the inventory, so a ledger written before the inventory's regeneration records disagreements that regeneration then removes |

**Which `ct-test` is measured.** The dev shell's `ct-test` is built by the
`ctTestTools` recipe in `flake.nix` from the `codetracer-src` flake input, and
the workspace `.envrc` auto-override redirects that input to a `../codetracer`
sibling checkout whenever one exists. On a workspace host it is therefore
whatever that sibling is, which is not necessarily the pinned revision.
`$CT_TEST` is the supported way to name a specific build, and the recorded
content hash is what ties the figures to it on any machine.

**The figures move with the surface.** A `ct-test` older than CodeTracer
`632fdceed` reads a Nim import clause one physical line at a time, so it does
not see `unittest` on a continuation line, and it reports every source that
imports `std/unittest` inside a multi-line bracketed clause as not
addressable. That difference is not a property of the suite. If the
integration test reports such sources, check which `ct-test` it found — and,
on a workspace host, the `../codetracer` sibling's revision — before
suspecting this repository.

**What the ground truth cannot see.** The two sides share no producer, which is
what makes their agreement informative. They do share a *definition*: both count
a case as a literal `test "…"` call in the source, and the checked-in inventory
carries no `--list-json`-derived count at all. A case declared through a
repository-local template — `testWithReturn` in the
`tests/integration/t_repro_test_runner_*` sources, or `gatedTest`, which
registers a case unconditionally and skips its body on a host that cannot run
it — appears in neither the numerator nor the denominator. The surface reports
zero cases for such a source, the inventory records zero, the two agree, and
none of those cases is addressable through `ct test`. They belong to the gap
between the percentages above and "every logical Reprobuild case", and nothing
in this measurement can find them.

## Why a source is not addressable

Each row of `unaddressableSources` carries a reason the script derives from the
source it names, and `tests/unit/test_ct_test_surface_addressability.py`
re-derives every recorded reason from the current source, so the reasons
cannot go stale unnoticed. The reasons are:

- **`shim-protocol-producer`** — the source imports the vendored
  `ct_test_unittest_parallel` shim instead of `std/unittest`. The provider's
  `frameworkForImport` matches the literal module names `unittest`,
  `unittest2` and `unittest_parallel`; the shim is none of them, so no
  framework is detected and the file falls through the generic non-test path.
  `libs/ct_test_unittest_parallel/tests/t_smoke_ct_test_unittest_parallel.nim`
  keeps the import on purpose. It is the shim's own smoke test: it calls
  `registeredTests()` and `currentProtocolMode()` to assert that the shim's
  `suite`/`test` overrides register the running binary's cases in-process.
  Moving it to `std/unittest` would delete its subject. Its cases are
  addressable through the shim's `--list-json` and run by this suite, but not
  through `ct test`.
- **`declares-no-cases-of-its-own`** — the source declares no literal suite or
  test. The generated `tests/bundles/bundle_*_pure_unit.nim` modules are the
  main case: each imports a set of test modules and declares nothing itself.
  Every member module is discovered under its own identity, so the bundle's
  cases are addressable; they are not addressable *under the bundle's* name,
  and they are counted as not addressable because the honest denominator is
  the tracked entry. Making such a row disappear needs a decision on which
  side owns the duplication: the surface could follow a Nim `import` of a
  test module and re-attribute its cases to the importer, which would put
  every member case in the catalog twice and turn each into an identity
  collision; or the inventory could stop attributing member cases to the
  aggregator, which is a change to this repository's scanner. A plain program
  with no unittest cases has this reason too.
- **`provider-multi-line-import`** — the source imports `std/unittest` in a
  bracketed clause spanning more than one line, and the surface measured
  predates `632fdceed` (see above).
- **`unclassified`** — the source imports `unittest` and is still not
  discovered. A row with this reason needs investigating; the script has no
  explanation for it.

## Identity stability

Identities are `<provider>/<language>/<framework>/<file>::<selector>`, e.g.

```
nim-unittest/nim/std/unittest/libs/ct_test_interface/tests/t_smoke_ct_test_interface.nim::t_smoke_ct_test_interface::t_smoke_ct_test_interface
```

The integration test checks two properties, rather than leaving them to
inspection:

* **Stable across invocations and scopes.** For a named six-source subset, the
  ids from the workspace-wide catalog are byte-identical to the ids from a
  per-file `--file` discovery, and each is exactly what the documented mapping
  predicts from that item's own file, suite and case name.
* **Unique across the whole catalog, bar the recorded collisions.** The
  identity is a slug — lowercased, whitespace collapsed to hyphens, `--`
  collapsed — so collisions are possible in principle. Every colliding
  identity is listed with its sites in `identityCollisions`, and the test
  requires that list to equal the collisions observed. Discovery is a static
  scan and is blind to `when` selection, so two declarations in mutually
  exclusive arms of a `when` (`when not defined(windows): … else: …`,
  `when defined(gostiAvailable)`, …) collide although at most one of them
  exists in any build. Such a collision costs no coverage. It shows that a
  `ct test` identity has no configuration dimension, so it cannot say *which*
  `when` arm it names. Check the sites before calling a collision a
  source-side duplication.

## What the surface cannot do

`ct test run` cannot execute a single case in this repository. This is
declared rather than incidental — the Nim provider's own `TestCapabilities`
carry `canRunProject = false`, `canRunFile = false`, `canRunSingle = false`.
It was run rather than inferred; this transcript is from the 2026-09-08
measurement under **History**:

```
$ ct-test test run --workspace <repo> --threads 4 --no-certificate
{"total": 10525, "dispatched": 10525, "executed": 0, "skipped": 0,
 "skipped_by_partition": 0, "passed": 0, "failed": 0, "unrunnable": 10523,
 "wall_time_ms": 111, "threads": 4, "verdict": "nothing-executed"}
errors: "provider 'nim-unittest' cannot run 10409 of the units dispatched to
         it, so they were discovered but never executed"
         "provider 'python-unittest' cannot run 114 …"
exit 2
```

Nothing is hidden: the surface reports the refusal as machine-readable
`unrunnable` counts, a per-provider `errors` array, and a distinct exit code
for "no test ran at all". The capability simply is not there yet.

This is why `scripts/run_tests.sh` was **not** changed to accept `ct-test` as
its runner. That lookup resolves an executor — `<bin> run --bin-dir=<dir>
--summary-json=<p> --results-dir=<d>` — and `ct test` differs from it in the
verb, in the input model (a source tree, not a directory of compiled
binaries), and in whether it can run anything at all. Teaching the lookup to
accept it by name would have produced a suite that executes zero tests. The
lookup now carries that reasoning in a comment where the next reader will find
it.

## Independence from the Reprobuild-only runner

Nothing in this measurement runs, links, or reads output from
`repro_test_runner`. Two structural facts make that checkable rather than
asserted:

1. The ground truth is the inventory artifact, produced by a separate scanner.
2. The test's last case points `$CT_TEST` at `build/bin/repro_test_runner` and
   requires the very first step — obtaining a catalog document — to fail. It
   does: `repro_test_runner test discover --workspace … --json` answers
   `repro_test_runner: unexpected positional: test`. Removing that redirection
   so the real surface is used instead makes the case fail, which is what
   shows the control discriminates rather than passing vacuously.

## History: the first measurement (2026-09-08)

Everything in this section describes `reprobuild` `origin/dev` at
`70801c670afafe9a381dacafb0f2002196d10e37`, plus the working-tree change that
added this report and moved the suite's test sources onto `std/unittest`. It
was measured once, on Linux 6.12.85 x86_64, against `ct-test` built from
CodeTracer `80c097309` (content hash `68f81fdcb9cc…`) with the `ctTestTools`
recipe; that revision later landed on CodeTracer's `dev` as `632fdceed`, with
the same tree. These figures are kept because they explain how the ledger got
its shape, and they are not updated.

At that revision the surface returned 10,525 items (8,510 cases, 2,015 suites)
in 3 catalogs. 1,480 of 1,482 tracked Nim suite sources (99.87%) and 8,286 of
8,371 tracked static cases (98.98%) were addressable. Per-source case counts
agreed on 1,479 of 1,480 sources, and there were 12 identity collisions, all
between mutually exclusive `when` arms. 94 cases in 17 sources were declared
through repository-local templates (13 through `testWithReturn`, 81 through
`gatedTest`) and so were invisible to both sides.

The one disagreement resolved in the surface's favour:
`tests/e2e/m68/t_e2e_repro_home_depends_on_topological.nim` declared a fifth
case inside a `when false:` block. The inventory scanner counted it, and
`ct test` did not. The surface evaluates a literal `when false` but not a
`when defined(…)`, so it dropped the dead case here and kept both arms of each
collision.

**What closed before that measurement.** Two causes had accounted for 85 of
the 86 rows in the measurement before it:

- **Multi-line imports (42 sources, 190 cases)** were a defect in the surface.
  The provider's framework scan was line-oriented: it parsed a line beginning
  `import ` and never read a continuation line, so a file was never recognised
  as a unittest source at all. Its diagnostic said the opposite of the truth:
  `info: no Nim unittest imports detected in file`. Reading an import clause
  as a statement fixed it, as CodeTracer `632fdceed`. Against the same tree, a
  `ct-test` without the fix reported 46 fewer addressable sources (1,434 of
  1,482).
- **Shim imports (43 sources, 57 cases)** were this repository's to close, and
  38 closed. The codetracer-nim fork now carries the shim's protocol inside
  `std/unittest` itself, in a strictly larger form: it adds `--catalog`,
  `bodyHash`, `group`, `threadsRequired`, `xfail`, `tags`, `deterministic`
  and a column, and keeps the protocol document off stdout. For a test source,
  replacing `import ct_test_unittest_parallel` with `import std/unittest` was
  a one-line change, and per-source `--list-json` catalogs built before and
  after were identical in case name, suite and line for all 38 sources (115
  cases). One behaviour is narrower: the shim's `--run` accepts a bare case
  name, a `suite::` prefix or an empty selector, while `std/unittest` matches
  only the full `suite::test`. Nothing here relies on the latitude, because
  `tools/test-runner` passes back the full `name` it read from the catalog.
  Four further rows were never shim rows. They import `std/unittest` in a
  bracketed clause and merely contain the string `ct_test_unittest_parallel`
  inside triple-quoted fixture modules. The classifier now reads a source with
  comments and string literals removed, and tests the bracketed-clause
  condition first.

The 13 `gatedTest` sources were among the 38 that stopped importing the shim.
Before that change they were not addressable; after it they were discovered as
zero-case files whose zero agreed with a zero-case ground truth. The source
percentage rose by 13 sources that carried 81 cases the surface still could not
name, without any line of the result table moving to say so.
