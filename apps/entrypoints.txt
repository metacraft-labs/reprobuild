# Windows-Runner-Binary-Cache-Deploy M7 (prereq a): --define:ssl so the main
# `repro` binary links OpenSSL/TLS and its EMBEDDED cache-consumer paths can
# speak https://. Without it, `repro infra apply`'s substitute path
# (substituteInProcess → http_pool.parseTarget) RAISES on an https:// cache
# URL ("https:// requires -d:ssl"), and the M5 `repro deploy-agent` manifest
# pull (agent.defaultHttpGet) has no way to TLS-wrap. With -d:ssl the same
# http_pool TLS path the M6 `repro-binary-cache-client` uses is compiled in,
# honoring REPRO_BINARY_CACHE_CA_FILE / REPRO_BINARY_CACHE_TLS_INSECURE. Plain
# http:// is unchanged. The reprobuild dev shell / nix build supplies the
# OpenSSL `-L` via NIX_LDFLAGS.
repro apps/repro/repro.nim --define:ssl --define:reproVendoredHash

# The attestation agent: the daemon an attested instance answers a challenge
# on. Its own binary rather than a `repro` subcommand, and deliberately: it
# sits inside every attested TCB, so what a verifier's trust extends over is
# its dependency closure, and the engine's is two orders of magnitude larger.
# No --define:ssl -- the API is loopback by default and a deployment that
# exposes it fronts it with its own authenticated channel, so linking TLS
# here would add an OpenSSL closure to every attested image to serve a
# transport nobody is meant to rely on (the binding, not the transport, is
# what makes the evidence trustworthy).
attestation-agent apps/attestation-agent/attestation_agent.nim
# Dependency-Attribution MAC-1: the thin daemon client. Links ONLY
# `repro_daemon_core` -- no build engine, no DSL runtime -- which is what
# keeps it at 802,880 bytes / 396 dyld fixups against `repro`'s 22,189,816 /
# 12,418 (debug images, macOS arm64; see the table in the module header), and
# therefore cheaper to start.
#
# `--opt:size` because the saving being bought here is image size: the fixup
# reduction is almost entirely REBASES, which scale with the image, not binds.
#
# `--define:reproVendoredHash` is load-bearing and NOT redundant, even though
# `config.nims` already selects the vendored backend by default. The dev shell
# exports `REPROBUILD_USE_SYSTEM_HASH_LIBS=1`, and `config.nims` reads it as
# `useSystemHashLibs = not defined(reproVendoredHash) and <that var is true>`.
# The define on this line is what makes the first conjunct false. Verified by
# counterfactual build: WITHOUT it this binary links libblake3 and libxxhash
# out of /nix/store and loads two more images before `main`; WITH it the only
# dylib is /usr/lib/libSystem.B.dylib. Measured cost of those two loads on an
# otherwise identical binary, 60 alternating runs: 3.16 ms against 2.33 ms,
# so 0.83 ms. That is 26% of this binary's whole start cost -- worth keeping --
# but it is NOT "a third of the saving": the end-to-end saving is ~20 ms and
# this is 4% of it. Do not quote it as the former.
#
# Both this row and `attestation-agent` above are now ALSO members of
# `repro.nim`'s `apps` collection, so `.#apps` / `.#release` build them and a
# release image carries them. `--opt:size` is the one flag on this row with no
# counterpart there: `nim.c` has no slot for it. See the comment on
# `reprobuild.apps.repro-client` for why that is acceptable.
repro-client apps/repro-client/repro_client.nim --opt:size --define:reproVendoredHash
