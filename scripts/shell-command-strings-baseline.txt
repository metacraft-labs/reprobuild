# shell-command-strings baseline — see scripts/check_shell_command_strings.sh
# Regenerate with: scripts/check_shell_command_strings.sh --write-baseline
# Then WRITE THE VERDICT for each entry: it is a defect until argued otherwise.
#
# Format: <file>|<exec api>|<operator classes>|<the offending literal(s)>
# Line numbers are deliberately absent so an edit above a site does not
# invalidate the baseline.
#
# Note what is NOT here. Three sites in the tree carry a redirect token and are
# provably shell-bound, so the scanner exempts them STRUCTURALLY rather than by
# baseline — that is the judgement this check exists to stop people
# re-deriving:
#   - the dev-session supervisor detach (`) </dev/null >> … 2>&1 &`) goes
#     through `execShellCmd`, which is a real shell on both platforms;
#   - the `setsid` cache-push detach lives in the `of wtPosix:` arm of a
#     `case targetOs`, and the `wtWindows` arm builds an argv;
#   - `runFixtureCmd` appends `>'…' 2>&1` to an explicit `sh -c` BODY with
#     `sh` as argv[0].
# Break any of those three properties and the site appears here.
