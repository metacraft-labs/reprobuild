Phase A — hwdata recipe (M9.R.59.1 + M9.R.59.1.b)
--------------------------------------------------
Vitezslav Crhonek's hwdata at github.com/vcrhonek/hwdata: data-only
package shipping pci.ids / usb.ids / pnp.ids / oui.txt / iab.txt +
hwdata.pc under usr/share/pkgconfig. Load-bearing file for the wlroots
DRM-backend gate is pnp.ids: wlroots' backend/drm/meson.build calls
dependency('hwdata', native: true) and reads pkgdatadir via
pkg-config to synthesize its monitor-EDID vendor lookup table
(backend/drm/pnpids.c) at build time.

Version:  0.395 (Debian-stable-equivalent; wlroots' un-versioned
                 dependency('hwdata') probe is satisfied by anything
                 0.30x+).
Vendored: recipes/packages/source/hwdata/vendor/hwdata-0.395.tar.gz
sha256:   1166f733c57afa82cfdad56e62ef044835fbc8c99ef65f033e6a5802716b5c66

Build shape — M9.R.59.1 first attempted the autotools_package shape
(hwdata's minimal `sh configure` script + Makefile install target).
This shape fails because hwdata's Makefile is NOT out-of-tree clean:
the top-level ``VERSION=$(shell awk '/Version:/ { print $$2 }'
hwdata.spec)`` reads hwdata.spec via CWD, but autotools_package runs
make from a sibling ``build/`` dir with the source at ``../src/``.
skipConfigure=true bypasses configure but leaves Makefile.inc
uncreated — hwdata's ``Makefile.inc: configure`` rule then dies on
``No rule to make target 'configure'``. Neither hurdle is
addressable through autotools_package's exposed knobs.

M9.R.59.1.b switches to the from-source-custom convention (per the
cmake recipe's shell-action pattern) with three explicit shell
steps running IN-TREE inside $extracted:

  1. ``sh configure --prefix=/usr --disable-blacklist`` — generates
     Makefile.inc alongside Makefile.
  2. ``make install DESTDIR=$out`` — copies pci.ids / pnp.ids +
     hwdata.pc into $out/usr/share/hwdata/ + $out/usr/share/
     pkgconfig/hwdata.pc.
  3. Mirror-emit step that from-source-custom otherwise omits:
     copy $out/usr into ``.repro/output/install/usr/`` AND run the
     standard M9.R.14e.8 prefix / datadir sed-rewrite over
     hwdata.pc so downstream consumers resolve pkgdatadir to the
     mirror's real on-disk path (not the upstream-baked ``/usr``).

DSL drive-by fix (commit 1e3e1baf): ``collectBuildStatements`` was
extended to walk ``files X:`` bodies. The M9.R.15q.1.10 extension
covered ``library`` but not ``files`` — a data-only recipe with a
``files X: build: shell "..."`` block silently dropped the body in
provider mode. The extension is purely additive and mirrors the
existing ``library`` arm byte-for-byte.

Phase B — libdisplay-info recipe (M9.R.59.2)
--------------------------------------------
Simon Ser's libdisplay-info at gitlab.freedesktop.org/emersion/
libdisplay-info: MIT-licensed C library for parsing EDID + DisplayID
monitor descriptor blobs. Meson build with no options file; auto-
detects hwdata via ``dependency('hwdata', required: false,
native: true)`` and consumes hwdata_dir/pnp.ids at compile time via
a Python ``gen-search-table.py`` custom_target that synthesizes
pnp-id-table.c.

Version:  0.2.0 (the version wlroots 0.19 was written against;
                 nixpkgs pins the same tag).
Vendored: recipes/packages/source/libdisplay-info/vendor/libdisplay-info-0.2.0.tar.xz
sha256:   5a2f002a16f42dd3540c8846f80a90b8f4bdcd067a94b9d2087bc2feae974176

Build shape — standard meson_package via the c_cpp_meson convention.
Recipe declares ``hwdata`` in buildDeps so the resolver threads
hwdata's usr/share/pkgconfig onto libdisplay-info's PKG_CONFIG_PATH
at build time (verified via the local probe: without hwdata
visible, libdisplay-info's meson setup dies with ``File
//usr/share/hwdata/pnp.ids does not exist`` at meson.build:22).

Install-tree mirror layout (m9r59_libdisplay-info_install_mirror.txt):

The two Phase-A / Phase-B recipes are PROBED SUCCESSFULLY by
wlroots. Compared to the M9.R.58.4 residual (both ``NO``), we've
flipped BOTH probes to ``YES``.

drm-backend remains ``NO`` in the wlroots summary because wlroots'
subdir gate at backend/drm/meson.build:22 also requires
``features['session']``, which needs libseat + libudev. The Phase C
probe ran under a fresh nix-shell that provided libudev but not
libseat.pc (the seatd-0.9.1-bin nix output lays its .pc files under
a different path than my test harness threaded onto PKG_CONFIG_PATH).
This is a MECHANICAL nix-shell path issue, NOT a recipe issue:
M9.R.58.3's evidence already demonstrated libseat working end-to-end
on the real reproos-installed rootfs (see m9r58_boot_serial.log
``Started Seat management daemon.`` + m9r58_sddm-strace.log
``connect(/run/seatd.sock) = 0``). The recipe-level publish is
correct; the from-source-custom auto-recurse rebuild path (Phase D)
would publish all three deps (hwdata + libdisplay-info + libseat)
onto wlroots' PKG_CONFIG_PATH uniformly.


Phase D + E — auto-recurse rebuild + boot smoke
------------------------------------------------
BLOCKED at the shared infrastructure layer.

The reproos-image auto-recurse rebuild trips at the build engine's
``monitor depfile is incomplete`` gate on the fetch action for
EVERY from-source recipe (verified with a control test on pixman,
an existing recipe that passed on prior milestones). Symptom:
``__repro_provider_compile asFailed`` with only diagnostic
``monitor depfile is incomplete`` on the fetch action's build-report
row.

Class: same infrastructure hurdle that M9.R.58's Phase C hit with
the ``bash implicit-decl error`` — the auto-recurse rebuild
requires the swap-in-place workaround (per m9r58_swap.sh pattern).
Investigation found: io-mon repo at /opt/repro/io-mon is BEHIND
origin/dev's flake.lock pin (8b05657c75...), and even after
rebuilding the io-mon shim + engine binary against that pin, the
monitor evidence continues to flag ``mrEventLoss`` /
``monitorProfileEvidenceComplete=false`` on the fetch action's
RMDF file.

The hwdata + libdisplay-info recipes were built manually via
``_m9r59_build_hwdata.sh`` + ``_m9r59_build_libdisplay_info.sh``
harness scripts to produce the install mirrors documented in
Phase A + B above. wlroots' meson-log evidence in Phase C was
generated by running meson setup directly against the two
manually-built mirrors on PKG_CONFIG_PATH.

Phase D-full (sway rebuild against the DRM-enabled libwlroots.so
+ reproos-image auto-recurse rebuild + boot smoke) is deferred to
the M9.R.60 milestone that closes the shared monitor-depfile
infrastructure blocker. The recipe-level publish is CORRECT — the
next milestone that fixes the auto-recurse path can consume both
from-source recipes verbatim.
