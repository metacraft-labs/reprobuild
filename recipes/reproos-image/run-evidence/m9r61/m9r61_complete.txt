Phase C — Linux-side fixes (M9.R.61.3)
---------------------------------------
Closed Candidate 1: `discardFragmentSlotAfterFork` did not reset
`readingSentinelActive` symmetrically with `closeFragmentSlot`. In
steady-state this is inert (the child's next `openFragmentSlot` at
writer.nim:524 clears the flag when it opens the child's own
fragment), but it left a documented soundness hole for future
refactors (vfork-preserved-pid variants + diagnostic samplers) that
would rely on the flag being correct BEFORE the next open. Landed
as defense-in-depth with the required regression test.

Candidates 2 + 3 not scoped for this milestone (not-yet-bisected
against a minimum-viable Linux reproducer). Phase B's residual
still stands: the pixman `__repro_provider_compile` still emits 182
kill-before-flush events on the hardened tip.


Phase D — Windows shim audit (M9.R.61.4 + M9.R.61.4.pin + audit)
-----------------------------------------------------------------
Audit found ONE critical + TWO documented gaps:

  Finding 1 (CRITICAL — LANDED) — repro_monitor_shim_flush and
    repro_monitor_shim_shutdown were both no-op `= 0` stubs on
    Windows, and the addExitProc callback only uninstalled inline-
    hook trampolines. Consequence: the ROUND-5 F kill-before-flush
    sentinel was NEVER retired by a matching committed marker on any
    Windows-side exit / execve path — every Windows capture ended
    with at least one un-matched pending per active thread, and
    mergeFragments' netting always injected synthetic loss records,
    false-downgrading completeness to mcIncomplete. Fixed in io-mon
    M9.R.61.4 by wiring closeFragmentSlot into all three Windows
    exit paths. Regression test lands on Windows only; validates the
    single-cycle + multi-cycle flush semantics.

  Finding 2 (MEDIUM — documented, not scoped) — no
    SetUnhandledExceptionFilter hook, so a process that dies via
    TerminateProcess / unhandled SEH / RaiseFailFastException /
    DebugBreak-in-a-non-debugged-process still escapes the flush
    path. Candidate fix shape documented in
    `m9r61_phaseD_windows_audit.txt`.

  Finding 3 (LOW — documented, not scoped) — no CreateJobObject
    supervisor (Windows counterpart of the Linux SIGCHLD supervisor
    the M9.R.61 task-brief flagged as the preferred long-term shape).

Reprobuild's flake pin bumped in M9.R.61.4.pin to include the
Finding 1 fix.
