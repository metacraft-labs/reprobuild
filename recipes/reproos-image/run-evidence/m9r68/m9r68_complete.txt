Phase D root-cause characterization (M9.R.68 out-of-scope; M9.R.69 owns)
-----------------------------------------------------------------------
Seatd binary is present at
`/usr/bin/seatd -> /opt/repro/reprobuild/recipes/packages/source/libseat/.repro/output/install/usr/bin/seatd`,
ELF64 x86-64, 65,624 bytes, dynamically linked (libc + ld-linux only,
inspected via ldd from host).  The crashes all report:

    RIP = 0x0000000000000002
    error = 14 (page fault on instruction fetch)
    "Unable to access opcode bytes at 0xffffffffffffffd8"

This is an indirect-call-through-uninitialised-function-pointer
pattern.  Given that the M9.R.58 residual close-out documented the
same "seatd builtin backend + logind backend both fail" class and
M9.R.59 landed hwdata + libdisplay-info to unblock wlroots's DRM
backend, but NOT a rebuild of libseat itself, the seatd binary in
this qcow2 was fetched into stage from the libseat install-mirror
whose backend (logind vs builtin) may not match the reproos-smoke
runtime (no logind D-Bus session, no libseat.so consumer up).

Concretely, M9.R.68 did NOT rebuild libseat between M9.R.58/59 and
now, so a stale binary from an earlier suboptimal libseat build may be
what's shipped.  M9.R.69's first move should be:

  1. rm -rf recipes/packages/source/libseat/.repro/build \
             recipes/packages/source/libseat/.repro/output
  2. repro build --tool-provisioning=from-source \
       recipes/packages/source/libseat
  3. Repeat boot smoke; if seatd still segfaults at ip=0x2, drop into
     minimal-repro under strace to identify the failing call site
     (candidate: unresolved GOT entry against a required libseat
     seatd-plugin symbol, or a chown()/setuid() failure path that
     leaves a fn pointer NULL and then calls it).
