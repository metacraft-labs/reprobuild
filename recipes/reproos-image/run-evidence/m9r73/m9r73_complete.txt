Phase A memo table summary
--------------------------
Per-loss-class invalidated-path-set predicate table lives in
`reprobuild-specs/Monitor-Loss-Path-Invalidation.md`. Highlights:

  * kill-before-flush         → Level 1, narrow, invalidated =
                                 action's declared OUTPUTS.
                                 Bounded by io-mon writer.nim:2201-2211
                                 per-thread mark/clear invariant.

  * unmonitored subtree/peer  → Level 2, session-wide (unbounded).
  * out-of-tree content       → Level 2, session-wide.
  * ambiguous unstamped frag  → Level 2, session-wide.
  * duplicate identity token  → Level 2, session-wide.
  * corrupt fragment          → Level 2, session-wide.
  * breakaway-report          → Level 2, session-wide.
  * unknown detail (default)  → Level 2, session-wide (R3 fail-closed).

The kill-before-flush narrow predicate ("this action's own declared
outputs") is a superset of the certainly-invalidated set: any
downstream cache entry can only observe the missed reads through this
action's own outputs, so bounding invalidation to those outputs is
sound. See the memo for the full rationale.

   on this Windows host. The Windows-only regression suite is a
   strong indicator but not a full recipe re-execution. The next
   Linux session should:
     cd /opt/repro/reprobuild
     rm -rf recipes/packages/source/pixman/.repro/build
     nix develop --command './build/bin/repro build recipes/packages/source/pixman'
   Expected: succeeds; trace shows narrow "cache-skip-monitor-loss"
   events ONLY for downstream actions whose inputs intersect a
   killed action's outputs — sibling actions get normal hits.

2. The classifier's "breakaway-report" prefix is retained defensively
   but no io-mon path currently emits an event-loss record with that
   prefix. Real breakaway-daemon reports fold as reads (not losses);
   authentication failures manifest as unmonitored-subtree losses.
   The prefix stays wired so a future io-mon change lands in a
   Level 2 conservative bucket by default.

3. The kill-before-flush narrow predicate is CONSERVATIVELY "this
   action's declared outputs". A tighter predicate ("only the
   specific paths the killed pid tried to read") would require a
   pid-to-paths reverse index io-mon does not export today. Per R3
   the current over-invalidation is the correct direction — no
   soundness hole.

4. New regression test file `test_m9r73_narrow_invalidation.nim` is
   NOT yet registered in `repro_tests.nim` (the main test runner
   catalog). It compiles + runs standalone via `nim c -r`. Adding it
   to repro_tests.nim is a follow-up mechanical wiring, out of scope
   here (would require also wiring the M9.R.72 tests that are also
   not yet in the catalog).
