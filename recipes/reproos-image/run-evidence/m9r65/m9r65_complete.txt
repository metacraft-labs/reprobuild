Phase A — SIGKILL sender identification (M9.R.65.1)
---------------------------------------------------
M9.R.64 attributed Class θ to "nim's parallel-compile pool
SIGKILL's outstanding children when it cancels".  Three orthogonal
lines of evidence falsified that hypothesis:

  * Full-workload strace filtered to
    `kill,tgkill,tkill,exit,exit_group` on the pixman build
    captured ZERO kill/tgkill/tkill syscalls.  Every one of the
    ~20 000 processes exited via `exit_group(0)`.  See
    /tmp/m9r65/strace-pixman.log (23 lines).

  * Nim compiler source audit
    (nim 2.2.4, compiler/extccomp.nim + lib/pure/osproc.nim):
    `execCmdsInParallel` uses `execProcesses`, which waits on all
    children via `waitpid(-1, ...)` and never sends a signal.
    A failing child triggers `rawMessage(errGenerated, ...)` →
    `handleError` (doAbort) → `quit(1)`.  `quit(1)` runs atexit
    and `_Exit`s — it does NOT kill outstanding siblings; those
    are reparented to init.

  * Minimal-reproducer bisection reduced the Class θ shape from
    182 records to a two-line test.  On the NixOS-WSL host this
    campaign runs on:

        io-mon --depfile /tmp/dep.rmdf -- /bin/sh -c "echo hi"
        → eventLoss=1 (the class-θ shape:
          argv=/nix/store/…-wrapped-sh/wrapper, emits=2,
          lastPath=/dev/tty, phase=emit)

        io-mon --depfile /tmp/dep.rmdf -- bash -c "echo hi"
        → eventLoss=0

    The difference is `/bin/sh` vs `bash`.  On this host `/bin/sh`
    is a symlink to a Rust `wrapped-sh` binary
    (/nix/store/…-wrapped-sh/wrapper) that calls `execvp` to chain
    into the real shell.


Phase B — root cause classification (M9.R.65.1)
-----------------------------------------------
The io-mon shim exports these exec family symbols
(nm -D /opt/repro/io-mon/build/lib/librepro_monitor_shim.so, BEFORE fix):

    T execl
    T execle
    T execv
    T execve
    T posix_spawn
    T posix_spawnp

It did NOT export:
    execvp, execvpe, execlp, fexecve

Every one of those unexported entry points also delegates to
`execve` (internally via a hidden reference, not via the PLT/GOT),
so LD_PRELOAD interposition on `execve` alone did not intercept
callers using the PATH-search variants.  When such a caller sits on
the process's first cycle after `mrFileOpen("/dev/tty")` (which
writes a pending read-tail marker), the intermediate `execvp`
transition leaves the pending marker un-paired: the shim's
`repro_hook_execve` doesn't fire, so no committed marker is
written, and `mergeFragments`' pending-vs-committed netting
injects one synthetic kill-before-flush record.

For the pixman workload, Nim's `execProcesses` unconditionally adds
`poEvalCommand` (osproc.nim:373), so every one of its 182
clang-wrapper `cc` invocations is dispatched through
`/bin/sh -c "…"`.  On the NixOS-WSL host `/bin/sh` is the Rust
`wrapped-sh` — 182 invocations, one orphaned pending marker each,
182 identical kill-before-flush event-loss records.

CLASSIFICATION: neither nim nor reprobuild sent SIGKILL.  The
shim's LD_PRELOAD table was missing exec-family entry points, and
the specific caller (NixOS-WSL's `wrapped-sh` Rust binary) always
uses one of the missing ones (`execvp`).


Phase C — fix decision + implementation (M9.R.65.2 in io-mon)
-------------------------------------------------------------
Fix went in io-mon (the right repo — the shim's exec interpose
table is the wrong side of the missing symbols).

Added to
`libs/io_mon/src/io_mon/hooks/linux_preload_runtime.nim`:

  * type-alias, real-function slot, and RTLD_NEXT-resolving real
    wrapper for each new entry point:
        ct_execvp_real_fn   / ct_linux_preload_real_execvp
        ct_execvpe_real_fn  / ct_linux_preload_real_execvpe
        ct_fexecve_real_fn  / ct_linux_preload_real_fexecve

  * `ct_linux_preload_dispatch_execvp` / `_dispatch_execvpe` /
    `_dispatch_fexecve` — each routes through the shim's existing
    `ct_execve_hook` (which emits `mrProcessExec` + flushes the
    fragment slot's committed marker via `repro_monitor_shim_flush`)
    then delegates to the real glibc entry via `real_execvp` /
    `real_execvpe` / `real_fexecve` (dlsym'd from RTLD_NEXT).

  * `execvp` / `execvpe` / `execlp` / `fexecve` public-symbol
    interposers with `visibility("default")`.  `execlp` builds the
    argv from its varargs (mirrors the existing `execl` /
    `execle` implementations).

The chained hook's real-execve call fails with ENOENT for the
relative-name case (which is fine — control returns to us and we
call the real execvp so glibc's PATH search + exec runs the
actual image).  For an absolute-path caller the chained
real-execve succeeds and the process becomes the new image
without ever returning to us.  Either way the shim's flush has
landed on disk.

AFTER-FIX exports:
    T execl     T execle
    T execl_p   T execlp    (execlp added)
    T execv     T execve
    T execvp    T execvpe   (both added)
    T fexecve                (added)
    T posix_spawn   T posix_spawnp

The fix required NO change to the shim's linux_preload.nim shim
policy or to the merge policy.
