Phase A — PAM configuration audit (M9.R.71.1)
---------------------------------------------
Full detail: m9r71_phaseA_pam_audit.txt.

Empirical mount of the M9.R.70 qcow2 established:
  * The from-source libpam-1.6.1 recipe does NOT recognize Debian's
    @include directive (only upstream `include` + `substack`).
    Confirmed via strings(1) on the from-source libpam vs Debian's
    libpam AND source audit of Linux-PAM-1.6.1/libpam/pam_handlers.c.
  * sddm-helper links against the from-source libpam via RUNPATH
    resolution.
  * /etc/pam.d/other uses four `@include common-*` lines that trip
    the "illegal module type" LOG_ERR path.
  * BUT the parser installs MUST_FAIL handlers and returns
    PAM_SUCCESS — cosmetic, not functional.
  * pam_systemd.so is `session optional` in
    /etc/pam.d/sddm-autologin, so its EIO return is IGNORED.
  * sddm.log's "sddm-helper exited with 6" == sway compositor
    SIGABRT (HelperApp.cpp:197 exit(status) forwards child
    exit code).

Real root cause: sway compositor crashes on launch.
Diagnostic gap: no wayland-session.log captured.

Genuine root cause (M9.R.71 residual)
-------------------------------------
Mesa version skew: from-source mesa recipe pins Mesa 23.3.6 (per
recipes/packages/source/mesa/vendor/mesa-23.3.6.tar.xz) but wlroots
0.19 requires Mesa 24+ for the DRI_IMAGE_DRIVER version 1 extension
that wlroots' GBM-backed EGL initialization consumes.

Mesa 23.3.6's swrast_dri.so exports `__driDriverExtensions_v2` with
DRI_IMAGE (image lookup + image loader) but NOT
DRI_IMAGE_DRIVER — that specific extension was added in Mesa 24.0's
DRI-driver refactor.  wlroots' egl.c:595 (create_gbm_device) fails
with "Failed to create GBM device" when DRI_IMAGE_DRIVER is absent.

Fix shape (deferred to M9.R.72+):
  Bump the from-source mesa recipe to Mesa 24.x (currently 24.3.6 or
  later).  Multi-week: requires cross-checking Mesa 24's build deps
  against the from-source graphics-stack recipes (libdrm 2.4.121+,
  libglvnd, wayland-protocols 1.32+, etc.), regenerating vendor
  tarballs, and retesting the whole reproos-image graphics path.
