Phase A — PAM stack audit (M9.R.58.1)
--------------------------------------
See m9r58_phaseA_pam_audit.txt in this dir.

Verdict: pam_systemd.so IS invoked (M9.R.56.8.6 wired it) and IS
reaching the dbus system bus (strace line 5292 in the M9.R.57
sddm-strace log), but the CreateSession() side-effect
``/run/systemd/users/1000`` is never created. Root cause traces to
M9.R.56.8.7's known dbus-lacking-``--systemd-activation`` gap —
logind's downstream call to PID-1 systemd (StartTransientUnit for
user@1000.service) fails and logind aborts CreateSession.

Falsifies the task-brief Shape-1 hypothesis (add pam_systemd to
the chain). Task-brief Shape-2 (systemd-run --user --scope) hits
the same dbus wall. Task-brief Shape-3 (enable-linger) requires
user@ to start once, same wall.

New Shape 5 chosen: enable libseat's ``seatd`` backend and run the
standalone ``seatd`` daemon as a system service before sddm.service.
This bypasses logind + user-manager entirely: libseat clients
(sway) connect to ``/run/seatd.sock``; seatd (running as root)
mediates /dev/dri and /dev/tty access via a Unix-domain socket
group check.

Phase C — swap-in-place + boot smoke (M9.R.58.3)
------------------------------------------------
The full auto-recurse rebuild via ``repro build recipes/reproos-image``
hits an implicit-decl error in bash (out of scope per M9.R.57), so
we followed the M9.R.57.5 swap-in-place pattern:

  1. qemu-nbd --connect + mount reproos-installed.qcow2 partition 2
  2. Copy new libseat.so.1 + seatd + seatd-launch into
     the libseat install-mirror path on the mounted rootfs
  3. patchelf: --set-interpreter + --set-rpath swap
     /nix/store/ → /repro/store/ (M9.R.46 convention); also
     PREPEND the Nix glibc lib dir to the RPATH so libc.so.6
     resolves to the SAME glibc that ld-linux-x86-64.so.2 came
     from (fixes M9.R.58.3 finding: mismatched ld/libc pair AVs
     seatd at __libc_start_main with ``seatd[N]: segfault at 2
     ip 0x2 error 14``)
  4. Shadow-link /usr/bin/seatd → install-mirror path
  5. Create ``seat`` group in /etc/group
  6. Write /etc/systemd/system/seatd.service + graphical.target.wants
     symlink
  7. Preserve /etc/ld.so.cache (M9.R.58.3 finding: deleting the
     cache panics init with ``Attempted to kill init! exitcode=
     0x00007f00`` since PID-1 systemd fails to load without it).
     Use ``ldconfig -r <root>`` via chroot to regenerate the cache
     with the new overlay path.

Phase D — wlroots DRM backend gate (M9.R.58.4)
----------------------------------------------
Root cause of the "Cannot create DRM backend: disabled at
compile-time" error at wlroots' ``backend/backend.c:276``:

The wlroots 0.19 meson probe for DRM backend requires FOUR
runtime deps: libdrm + libgbm + hwdata + libdisplay-info. The
pre-M9.R.58.4 wlroots recipe declared libdrm only (mesa was
missing entirely). meson-log.txt confirms:

  Package gbm was not found in the pkg-config search path.
  Run-time dependency gbm found: NO (tried pkgconfig and cmake)
      drm-backend      : NO
      gles2-renderer   : NO
      gbm-allocator    : NO

M9.R.58.4 adds ``mesa`` to wlroots buildDeps. Fresh rebuild:

  Run-time dependency gbm found: YES 23.3.6
  Dependency gbm found: YES 23.3.6 (cached)
      drm-backend      : NO       <-- still NO
      gles2-renderer   : YES      <-- was NO
      gbm-allocator    : YES      <-- was NO

drm-backend is still NO because two MORE recipes remain missing
(neither has a from-source recipe in this repo yet):

  Package hwdata was not found in the pkg-config search path.
  Build-time dependency hwdata found: NO (tried pkgconfig and cmake)
  Package libdisplay-info was not found in the pkg-config search path.
  Run-time dependency libdisplay-info found: NO (tried pkgconfig and cmake)

These are the last two upstream deps of wlroots' DRM backend on
wlroots 0.19. Adding recipes for them is out of scope for M9.R.58
(which was scoped to the libseat runtime residual). Documented
here as the M9.R.58 residual.

Residual — hwdata + libdisplay-info from-source recipes
-------------------------------------------------------
Strictly smaller than the M9.R.57 residual:
  * M9.R.57 residual: libseat's TWO backends (logind + builtin)
    both fail at runtime with logind IPC + tty permission errors —
    a systemd + PAM + SDDM + logind integration issue with no
    obvious clean fix without a dbus rebuild.
  * M9.R.58 residual: TWO from-source recipes are missing (hwdata
    + libdisplay-info). Both are small pure-C libraries with
    well-understood upstream release cadences; each is a
    self-contained M9.K-style recipe following the libseat /
    libinput precedent (~1 file each, ~50-100 lines).

Candidate follow-up work for M9.R.59:
  * Add recipes/packages/source/hwdata/repro.nim (upstream
    https://github.com/vcrhonek/hwdata; MIT-licensed data-only
    package; wlroots consumes hwdata's pci.ids for the DRM
    connector labeling)
  * Add recipes/packages/source/libdisplay-info/repro.nim
    (upstream https://gitlab.freedesktop.org/emersion/libdisplay-info;
    small C library, meson-built; wlroots consumes it for EDID
    parsing)
  * Declare BOTH in wlroots buildDeps
  * Rebuild wlroots; expect ``drm-backend : YES`` in meson-log.txt
