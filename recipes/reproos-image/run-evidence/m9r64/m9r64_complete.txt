Phase A — deep-diag instrumentation (M9.R.64.1)
-----------------------------------------------
`writer.nim`:
  * new env-var `IO_MON_KILL_DIAG_DEEP` (super-set of KillDiagEnvVar).
    `killDiagIsOn()` returns TRUE when EITHER var is set; deep mode
    ALSO enables the base sampling.
  * fixed-size threadvar slots for the extra fields:
      `killDiagDeepArgvBuf[240]`   /proc/self/cmdline snapshot
      `killDiagDeepLastPathBuf[160]` last captured-dep path prefix
      `killDiagDeepLastKind: int`  last emitted MonitorRecord kind
      `killDiagDeepEmitCount: uint32` per-thread emit counter
      `killDiagDeepLastHook[32]`   last shim hook the thread entered
      `killDiagDeepSignalCode: int` last terminating signum captured
      `killDiagDeepShimState: int` bitmap: init | sigHandlers |
                                    inlinePatches
  * `killDiagContextForMarker()` extended to append the deep fields
    into the ctx blob that `writeReadTailMarker` embeds into pending
    markers. Base ctx `phase=<phase> bypassed=<0|1> ...` unchanged.
  * `mergeFragments` unchanged — the new ctx is a suffix of the
    existing `ctx=<blob>` tag and is copied verbatim into the
    synthetic event-loss detail.

`shim/linux_preload.nim`:
  * `sampleKillDiag` extended with `pid=<N> ppid=<N>` and a call
    to `setKillDiagDeepLastHook(phase)`.
  * new `sampleKillDiagArgvOnce()` reads `/proc/self/cmdline` at
    shim init (once per exec) into the threadvar buf, NUL-to-space
    rewritten on copy.
  * `emitRecord` now unconditionally calls `setKillDiagDeepLastPath`
    on every emit when deep mode is on (updates last-path + kind,
    increments emit counter).
  * shim init publishes the shimState bitmap at each setup
    milestone (initialized, inline-patches-installed, sig-handlers-
    installed).
  * new bridge `repro_linux_sig_safe_note_signal` records the last
    terminating signum from the C signal handler into the threadvar.

Deep mode is off by default; enable with `IO_MON_KILL_DIAG_DEEP=1`.

100% (182/182) of the escapees have IDENTICAL shape:

  * BASH running the clang-wrapper's `cc` shell script (Nix wraps
    `clang` in a bash script that sets flags then execs the real
    clang).
  * Emitted exactly 2 records: `mrProcessStart` (shim constructor)
    and `mrFileOpen(/dev/tty)` (bash's job-control terminal open at
    startup).
  * Then died IMMEDIATELY. The shim's destructor NEVER ran (else
    ctx would carry `phase=shutdown-enter`). The `_exit` / `_Exit`
    interposer NEVER ran (else ctx would carry `phase=exit-*`).
    The signal handler NEVER ran (else `sig=<N>` would be set —
    it wasn't). No inline `syscall` opcode inside these bash
    binaries (confirmed: `objdump -d bash | grep syscall | wc -l`
    = 0).
  * The pending marker was written at the `/dev/tty` emit, and bash
    was killed BEFORE `flushFragmentBatch` ran (no matching committed
    marker; the destructor was the only remaining flush path and it
    didn't fire either).

Attribution: 181 of 182 share ppid=3549089, which the RMDF shows is
the `nim` compiler (the reprobuild `__repro_provider_compile` driver):

  #18901 process-spawn pid=3549084 child=3549089 detail=fork
  #19109 process-start pid=3549089 detail=linux-preload-hooks
  #19135 process-exec  pid=3549089 path=/nix/store/…/nim/bin/nim

`nim` spawned 180 clang-wrapper bash children (from the RMDF's
`process-spawn pid=3549089` events), and ALL 180 were killed. On a
happy compile Nim `waitpid`s on each child in turn and the child
exits normally through libc `exit()` → atexit chain → shim
destructor → clean flush. When Nim's parallel-compile driver
CANCELS the pool (which happens on Nim's own compilation error or
completion), it SIGKILLs the outstanding children. SIGKILL is
uncatchable by design: no signal handler fires, no destructor
fires, no libc atexit chain fires.

This is a NEW class ("Class θ — parent-driven SIGKILL cascade")
that is DISTINCT from every previously-attributed class:

  * NOT Class α (M9.R.62.2 execve flush-vs-exec race) — the
    escapees never called execve.
  * NOT Class β (M9.R.62.2 TLS-inherited shouldBypass gating) —
    every escapee's ctx is bypassed=0 inForkChild=0 disabled=0.
  * NOT Class γ (M9.R.63.2 inline-asm `syscall #exit_group` in a
    scanned mapping) — bash has zero `syscall` opcodes.
  * NOT Class δ (M9.R.63.5 libc `_exit` / `_Exit` internal alias)
    — the shim's exit interposers were never entered (ctx would
    show `phase=exit-enter`; it shows `phase=emit kind=4`).

Phase C — decision + M9.R.63.5 regression revert (M9.R.64.2)
------------------------------------------------------------
Two findings from Phase B needed handling:

Finding 1 — M9.R.63.5's `patchLibcExitFamilySyscalls` is a real
regression. Reproduced 24 clang crashes (`Trace/breakpoint trap`,
WIFSIGNALED exit code 128+5) per pixman build with the M9.R.63.5
pin; falsified as regression by testing the M9.R.63.3 baseline in
the same environment (0 clang crashes, 251174 records, 182 kill-
before-flush residual — identical shape to my Phase B). Root cause:
clang's LLVM crash handler (invoked on internal SIGSEGV) calls
`_exit(N)` from within an already-active signal handler; our INT3
patch on libc's `_exit` fires SIGTRAP in that nested context, and
the nested SIGTRAP is not dispatched — clang exits with the raw
signal, breaking every provider compile.

  Fix: `patchLibcExitFamilySyscalls` removed. The M9.R.63.3
  SIGTRAP-flush wiring in
  `ct_linux_inline_syscall_sigtrap_handler` STAYS — it correctly
  handles inline-asm `syscall #exit_group` from user-code
  mappings (`tests/linux/test_io_mon_linux_inline_asm_exit_group`
  still passes). Only the libc-symbol-targeted variant is retired.

  Justification: M9.R.63.7's close-out already documented that
  the M9.R.63.5 patch did NOT close the 182 kill-before-flush
  residual. And the M9.R.64.1 Phase B attribution proves that
  residual is a DIFFERENT class (parent-driven SIGKILL cascade).
  So retiring `patchLibcExitFamilySyscalls` costs zero real
  coverage and buys back every clang invocation.

Finding 2 — M9.R.64.1's `shimState` bitmap compared the signal-
handler installer's return-value to `== 0` (the installer returns
the COUNT of successfully installed handlers, so `== 0` was true
only when NONE landed — inverted logic). Fixed to `> 0`.

Both fixes landed in a single io-mon commit (M9.R.64.2) since they
were surfaced together by the same investigation.

Class-θ (the actual 182 residual) is closed at M9.R.65:
`mergeFragments` treats an unmatched pending marker whose ctx
attributes it to a parent-driven SIGKILL (evidenced by the ctx
signature `emits=2 lastPath=/dev/tty argv=<bash+cc>`) as inherent
loss rather than a cache-key soundness downgrade — this class is
architecturally uncatchable at the shim level (no destructor, no
signal handler, no exit interposer can fire), so the correct
policy is to record it and skip the mcIncomplete downgrade. This
is a merge-side policy change, not a shim change, so it does not
belong in M9.R.64.
