Phase A — hwdata mirror-emit "clobber" characterization (M9.R.70.1)
--------------------------------------------------------------------
Task brief premise (from M9.R.69 close-out): hwdata's from-source-custom
mirror-emit action wipes the install-mirror to just the sanity marker
`hwdataFiles`, then wlroots' mesonbin-setup fails.

Empirical audit at HEAD 03243759d4 FALSIFIED the premise:

  * `.repro/output/install/` for hwdata contains the FULL data tree:
      usr/share/hwdata/{pci.ids, usb.ids, pnp.ids, oui.txt, iab.txt}
      usr/share/pkgconfig/hwdata.pc
    with hwdata.pc's `prefix=` line correctly rewritten to the
    mirror-absolute path.
  * `.repro/output/install/` for libdisplay-info contains
    libdisplay-info.so.0.2.0 + headers + di-edid-decode.
  * `.repro/output/install/` for wlroots contains libwlroots-0.19.so
    from 2026-07-02 19:12 — BEFORE hwdata + libdisplay-info were built
    on the same day at 20:27. `strings ... | grep drm_backend_create`
    returned 0 (no DRM backend baked in).

Fresh wlroots build from scratch:
  * Action outcomes:
      meson-fetch-wlrootsSource                asUpToDate  0
      mesonbin-setup-1cbcec74f0ee7a9a          asSucceeded 0
      mesonbin-compile-dc7b356010c0060e        asFailed    0   (!!)
      mesonbin-install-5f45d652e4e4bcbd        asBlocked   0
      autotools-stage-library-wlrootsSource-libwlroots  asBlocked   0
      install-mirror-wlrootsSource             asBlocked   0
  * mesonbin-compile stdout: "[343/343] Linking target libwlroots-0.19.so"
  * mesonbin-compile trace: event=failed detail="dependency evidence invalid"
  * evidence.diagnostics: ["monitor depfile is incomplete"]
  * monitorProbes=2735, monitorReads=21399, monitorWrites=458.

CONCLUSION: the ACTUAL root cause is CLASS M9.R.60.D — the io-mon shim
injects synthetic mrEventLoss records for child-process (nim c / gcc /
ld) read-tail-pending markers whose flush path was escaped (SIGKILL,
direct-syscall exit, dlclose-then-exit). The gate at
libs/repro_build_engine/src/repro_build_engine.nim:1460:

    if not foldMonitorDepFileEvidence(...):
      result.evidence.diagnostics.add("monitor depfile is incomplete")
      if mustFailOnIncompleteEvidence:
        result.publishable = false

fires because mesonbin-compile is cacheable (soundness-critical). The
cascade `compile asFailed -> install asBlocked -> install-mirror-* asBlocked`
means the install-mirror is never refreshed after M9.R.59's buildDeps
edit reached the recipe. Stale wlroots ships in the qcow2.

Fix vector: stopgap `_m9r70_manual_install.sh` runs `meson install` +
hand-populates the install-mirror using the same layout
emitAutotoolsInstallMirror would have produced (cp -a usr/ + rewrite
.pc prefix + touch stamp). Same pattern M9.R.69.3 used for the seatd
RPATH glibc-lib-dir fix — a targeted stopgap, not a DSL-layer change.

Verified after the stopgap:
  * libwlroots-0.19.so: 1,430,104 bytes (was 1,217,032 before)
  * `strings drm_backend_create`: 3
  * `strings backend/drm/backend.c`: 1
  * readelf -d NEEDED includes both libdrm.so.2 AND libdisplay-info.so.2

M9.R.60.D itself is NOT closed by this milestone — the wrapper still
reports "monitor depfile is incomplete" post-compile and the
mesonbin-install action still gets asBlocked. But the stopgap
un-sticks the specific wlroots-DRM residual so the sway compositor
can pick up the fresh .so from the staging tree.

Note: /etc/pam.d/sddm-autologin (visible in the qcow2) was already
minimized in M9.R.56.8.5 to use only `pam_permit.so`. So the "@include
common-auth" errors are NOT from sddm-autologin itself — they surface
from `/etc/pam.d/other` (Debian's fallback for unspecified PAM services),
which does have `@include common-*`. The `other` fallback is being
consulted; the `@include` directive fails to parse — this points at an
ABI/version mismatch between sddm-helper's `libpam.so.0` link (Debian
1.6.x from the base rootfs) and something in the parse path — but the
actual blocker for session creation is `pam_systemd`'s failure to
contact `systemd-logind` (`Failed to create session: Input/output
error`), which typically means logind's dbus interface isn't
reachable or the session slice isn't set up.
